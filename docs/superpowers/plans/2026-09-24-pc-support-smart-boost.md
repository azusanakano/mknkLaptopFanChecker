# PC共通対応・自動スマートブースト Implementation Plan

> **For agentic workers:** Execute inline with superpowers:executing-plans; request one final review after verification.

**Goal:** ノート専用表記を廃止し、PC共通の冷却監視と、メモリ使用率に応じる自動スマートブーストを提供する。

**Architecture:** 既存の監視・設定・トレイを維持する。CPU冷却センサー選択を独立した検証可能な処理にし、メモリ整理は独立したバックグラウンド処理と純粋な発火条件に分離する。

**Tech Stack:** Windows 10/11 x64, WinForms, .NET Framework 4.7.2, LibreHardwareMonitor 0.9.6, Windows API.

**Spec:** ユーザーの「ノートでもデスクトップでも使用」「全体レビュー」と、追加指定「メモリ使用率を監視して、自動実行のみのシンプルな形」を実装する。

## Global Constraints

- 表示名は「ネコシステム社 CPUファンチェッカー」。内部EXE名・保存先・起動タスク識別子は更新互換性のため維持。
- 自動ブーストの操作はON/OFFだけ、初期OFF。85%以上が30秒継続した場合に発火し、再試行も含め30分以上空ける。
- ファンテスト中・デモ中・終了時にはメモリ整理を実行しない。プロセス終了・ファイル削除・電源設定変更は行わない。
- メモリ整理は同じユーザー・セッションの非クリティカルなバックグラウンドアプリだけ。前面アプリ、Windowsプロセス、本アプリは対象外。
- 実機上の自動メモリ整理は開発中に起動せず、テスト専用プロセスと純粋な発火条件で確認。

## Review Focus

1. ケースファン・ポンプ・未接続ヘッダーをCPUファンの正常判定根拠にしない。
2. 複数CPUの高温と距離センサーを区別し、温度喪失時に負荷を止める。
3. 高メモリの短いスパイク、データ欠損、OFF、ファンテストをまたいで発火しない。
4. メモリ整理と検査の競合、終了中のUI通知、権限不足を安全に扱う。
5. 最小画面サイズ、既存設定、自動起動、配布EXEの表示名を維持・検証する。

## Execution ledger

- 既存の未コミット変更（GHz・CPU構成表示）をそのまま維持する。
- ユーザーの追加指定により一時ファイル削除・手動ブースト・PC Manager起動連携は対象外。
- このPCではC++ Build Toolsがない。ランチャーのコードを変更せず、必要な表示メタデータの更新と検証を実施する。
- 判定・CPU構成・クロック・自動実行条件・設定保存など101件のテストに成功。
- Windows APIを使う隔離テストで物理メモリ取得、本人・別ユーザー・別セッション・キャンセルの除外を確認。作成した子プロセスだけを整理し、継続動作とワーキングセット低下を確認。
- 1450×1100および1040×700のデモ描画、GHz・CPU構成・メモリ表示、デモ中の自動処理禁止を確認。
- センサー例外、温度欠損、CPU直結からACPIへの切替時に負荷停止を確認。負荷ワーカーの独立した時間制限も検証。
- レビューで開始確認ダイアログ中の競合と実行時刻保存失敗時の実行を修正し、再レビューで残るP1/P2なし。
- ネイティブランチャーはVERSIONINFOとマニフェストのみ更新。x64 GUI形式と、リソース以外の10セクションのSHA-256一致を確認。
